Проблема

Ошибки в ТЗ становятся инцидентами в проде

~4 ч

уходит у аналитика на ручную проверку одного ТЗ

Что пропускают

  • двойное списание при таймауте
  • CVV и номер карты в логах
  • DECLINED в одном разделе, REJECTED в другом

Почему банк не доверяет ИИ

  • «ИИ сольёт данные клиентов»
  • «ИИ начнёт галлюцинировать»
  • «что он сделал, не проверить»

Нужен агент, который находит такие дефекты за минуты и которому банк может доверять.

Решение

ТЗ на входе, доказанные дефекты и готовые правки на выходе

Получаете

Правка«было → стало» и Gherkin-сценарии, проверенные агентом
Трейскакой агент нашёл и почему арбитр оставил

Пример из демо

п. 4.3: «при ошибке запрос повторяется»

Blocker: нет ключа идемпотентности, и сетевой таймаут приводит к двойному списанию.

Правка: обязательный Idempotency-Key, хранение результата 24 ч, сценарии Given / When / Then.

SpecAgent3
Главная идея

Разделяем «мозг», «руки» и «память»

Подход из инженерной статьи Anthropic о Managed Agents. Агент, у которого всё в одном процессе, при падении теряет работу, а секреты в нём лежат рядом с кодом модели.

Session · память

Журнал событий, только дописывается. Единственное состояние системы и готовый аудит-трейл.

У нас: PostgreSQL, таблица audit_events

Brain · мозг

Агенты без состояния. Любой воркер можно убить: новый вызывает wake(sessionId) и продолжает.

У нас: C#-оркестратор и 9 агентов на Qwen

Hands · руки

Инструменты за одной дверью execute(name, input). Секретов внутри нет.

У нас: чтение ТЗ, поиск по стандартам, рендер .docx

«Cattle, not pets»: воркеры заменяемы, их не «лечат» при падении.

Источник: anthropic.com/research/managed-agents4

Периметр безопасности

Модель видит только токены

ТЗ→ Parser→ PII Masker→ Журнал (токены)→ Агенты + Qwen→ Demasker→ Отчёт
Что маскируемКак отличаем от просто чисел
ИИН / БИН → [IIN_1]контрольная сумма mod 11
Номер карты → [PAN_1]алгоритм Луна
IBAN KZ, телефон, e-mail, IP, ключистрогие шаблоны
  • PII Vault единственный знает «токен ↔ значение»
  • Demasker единственная точка выхода реальных данных
  • Одно значение даёт один токен: агенты всё ещё видят связи между разделами
  • Текст ТЗ для модели только данные, а не команды

Eval & Ablation

На каждой новой модели проверяем: нужен ли ещё этот этап? Обходной путь для одной модели может оказаться лишним для следующей.

Сравниваем три варианта: только правила, один промпт и полный SpecAgent. Цифры появятся после прогона на датасете; здесь мы их не придумываем.
