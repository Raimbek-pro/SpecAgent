# FinTech security checklist

Curated checklist the compliance and distributed-systems critics search (kb.search). Keep each item short and testable. Add sources in brackets.

## Идемпотентность операций списания
- Каждая операция, меняющая баланс, принимает ключ идемпотентности (заголовок Idempotency-Key, UUID v4).
- Повтор запроса с тем же ключом возвращает сохранённый результат, а не выполняет операцию заново.
- Срок хранения ключей ≥ 24 ч; конфликт ключа с другим телом запроса → 422.

## Таймауты и ретраи
- Для каждого внешнего вызова (процессинг, платёжная система, SMS, KYC-провайдер) задан таймаут.
- Ретраи только для идемпотентных вызовов, с экспоненциальным backoff и jitter, ограниченное число попыток.
- Статус UNKNOWN (таймаут после отправки) обрабатывается статус-запросом и сверкой, а не повтором списания.

## Компенсации (Saga)
- Для многошаговых операций описаны компенсирующие действия на каждый шаг (reversal, отмена холда).
- Определено, кто и когда запускает компенсацию и что видит клиент.

## Гонки и параллелизм
- Списание с одного счёта сериализовано (блокировка строки / оптимистичная версия).
- Двойной клик / параллельные сессии не приводят к двум операциям.

## Сверка
- Ежедневная сверка с внешней стороной, обработка расхождений описана.

## Карточные данные (PCI DSS)
- CVV/CVC не хранится после авторизации ни в каком виде [PCI DSS v4.0 req. 3.3.1].
- PAN хранится только зашифрованным или токенизированным; отображается маскированным (первые 6 / последние 4) [PCI DSS v4.0 req. 3.4, 3.5].
- PAN и CVV не попадают в логи, трассировки, аналитику.

## 3-D Secure и аутентификация
- Для операций по карте без присутствия клиента — 3-D Secure 2.x; допустим risk-based (adaptive) подход с challenge выше лимита.
- Ограничение попыток ввода OTP, блокировка и уведомление.

## Доступ
- Ролевая модель (RBAC) описана; проверка владения объектом на каждом запросе (защита от IDOR).
- Срок жизни сессии/токена задан; refresh-токены отзываются.
- Аудит-лог действий с ПДн и деньгами (кто, что, когда), неизменяемый.

## KYC / AML
- Определены лимиты на операцию / день / месяц в зависимости от уровня идентификации клиента.
- Операции проходят AML-скоринг; описано поведение при подозрительной операции (холд, ручная проверка).

## Деньги в данных
- Суммы — decimal или целое в минимальных единицах (тиын); валюта указана явно (ISO 4217).
