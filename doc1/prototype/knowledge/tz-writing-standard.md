# Стандарт написания ТЗ (внутренний)

## Структура
- Цели и границы, глоссарий, роли, пользовательские сценарии, функциональные требования, нефункциональные требования, интеграции, модель данных, коды ошибок, критерии приёмки.

## Требование хорошее, если оно
- атомарно (одно требование — одна проверка);
- однозначно (без «быстро», «удобно», «при необходимости»);
- измеримо (числа, единицы, условия);
- проверяемо — есть критерий приёмки в формате Gherkin (Given / When / Then);
- непротиворечиво с другими разделами (единые названия статусов, сущностей, ошибок).

## Нефункциональные требования
- Производительность: RPS, latency p95/p99.
- Доступность: SLA %, RTO, RPO.
- Хранение: сроки, объёмы, резервное копирование.

## Интеграции
- Для каждого внешнего вызова: контракт, таймаут, ретраи, идемпотентность, коды ошибок, поведение при недоступности.
